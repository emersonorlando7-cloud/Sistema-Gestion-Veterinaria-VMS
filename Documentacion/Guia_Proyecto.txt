1. CONFIGURACIÓN DE VIRTUALBOX Y RED (TODOS LOS SERVIDORES)
═══════════════════════════════════════════════════════════════════════
Objetivo: Crear la red privada para que las 5 máquinas se comuniquen.

Paso 1.1: Crear Red Host-Only en VirtualBox
- Ir a Archivo > Herramientas > Administrador de Red.
- Crear red "Solo Anfitrión". IPv4: 192.168.56.1, Máscara: 255.255.255.0, DHCP: Desactivado.

Paso 1.2: Configurar Adaptadores en cada VM
- Adaptador 1: NAT (para internet).
- Adaptador 2: Host-Only (para la red interna del proyecto).

Paso 1.3: Asignar IPs Estáticas (Netplan)
# Abre el archivo de configuración de red con permisos de superusuario.
sudo nano /etc/netplan/01-netcfg.yaml

# Contenido del archivo:
network:
  version: 2 # Versión del formato YAML que usa Ubuntu.
  renderer: networkd # Gestor de red nativo de Ubuntu (systemd-networkd).
  ethernets:
    enp0s3:
      dhcp4: yes # Interfaz NAT: pide IP automática al router para tener internet.
    enp0s8:
      dhcp4: no # Interfaz Host-Only: NO pide IP automática, usará IP fija.
      addresses:
        - 192.168.56.11/24 # Asigna la IP estática y la máscara de subred.
      nameservers:
        addresses: [8.8.8.8, 1.1.1.1] # Servidores DNS de Google y Cloudflare.

# Restringe los permisos del archivo para que solo root pueda leerlo (seguridad).
sudo chmod 600 /etc/netplan/01-netcfg.yaml
# Aplica los cambios de red y activa la nueva IP.
sudo netplan apply

Paso 1.4: Hostnames y /etc/hosts
# Cambia el nombre del servidor para que coincida con su rol (ej. app-01).
sudo hostnamectl set-hostname app-01
# Abre el archivo de mapeo de nombres de dominio locales.
sudo nano /etc/hosts

# Contenido del archivo /etc/hosts:
127.0.0.1       localhost
127.0.1.1       app-01 # Nombre local de esta máquina.
192.168.56.10   lb-01 # IP del balanceador.
192.168.56.11   app-01 # IP de este servidor.
192.168.56.12   app-02 # IP del segundo servidor de app.
192.168.56.13   db-01 # IP de la base de datos principal.
192.168.56.14   db-02 # IP de la base de datos de respaldo.

# Comprueba que la red y la resolución de nombres funcionan.
sudo ping db-01

2. SERVIDORES DE BASE DE DATOS (db-01 y db-02)
═══════════════════════════════════════════════════════════════════════
Objetivo: Configurar la replicación y las tablas para citas y bitácora.

Paso 2.1: Instalación
# Actualiza la lista de paquetes disponibles en el repositorio.
sudo apt update
# Instala el servidor de base de datos MySQL sin pedir confirmación.
sudo apt install mysql-server -y

Paso 2.2: Configuración de mysqld.cnf
# Abre el archivo de configuración de MySQL.
sudo nano /etc/mysql/mysql.conf.d/mysqld.cnf

# Agrega debajo de la sección [mysqld]:
[mysqld]
server-id = 1 # Identificador único del servidor. En db-01 es 1, en db-02 es 2.
bind-address = 0.0.0.0 # Permite que MySQL acepte conexiones desde cualquier IP.
max_connect_errors = 100000 # Aumenta el límite de errores de red para evitar bloqueos de IP.

# Reinicia el servicio de MySQL para aplicar los cambios.
sudo systemctl restart mysql

Paso 2.3: Creación de Usuarios
# Entra a la consola interactiva de MySQL como administrador del sistema.
sudo mysql

# Crea el usuario para la replicación.
CREATE USER 'replicator'@'%' IDENTIFIED WITH caching_sha2_password BY 'ReplicaPass123!';
# Le otorga el permiso específico para copiar datos entre bases.
GRANT REPLICATION SLAVE ON *.* TO 'replicator'@'%';

# Crea el usuario para la aplicación.
CREATE USER 'app_user'@'%' IDENTIFIED WITH caching_sha2_password BY 'AppPass123!';
# Crea un acceso específico para cuando la petición viene desde la IP de HAProxy.
CREATE USER 'app_user'@'192.168.56.10' IDENTIFIED WITH caching_sha2_password BY 'AppPass123!';
# Otorga todos los privilegios sobre la base de datos de la veterinaria.
GRANT ALL PRIVILEGES ON vet_clinic_db.* TO 'app_user'@'%';
# Otorga privilegios para el acceso específico desde HAProxy.
GRANT ALL PRIVILEGES ON vet_clinic_db.* TO 'app_user'@'192.168.56.10';
# Recarga los permisos en memoria para que se apliquen inmediatamente.
FLUSH PRIVILEGES;
# Sale de la consola de MySQL.
EXIT;

Paso 2.4: Creación de Base de Datos y Tablas (Solo en db-01)
# Crea la base de datos del proyecto.
CREATE DATABASE vet_clinic_db;
# Selecciona la base de datos para trabajar dentro de ella.
USE vet_clinic_db;

# Tabla de usuarios del sistema.
CREATE TABLE users (id INT AUTO_INCREMENT PRIMARY KEY, username VARCHAR(50) UNIQUE NOT NULL, password_hash VARCHAR(255) NOT NULL, role VARCHAR(50) NOT NULL);
# Tabla de dueños de mascotas.
CREATE TABLE owners (id INT AUTO_INCREMENT PRIMARY KEY, name VARCHAR(100) NOT NULL, phone VARCHAR(20), email VARCHAR(100), address VARCHAR(255));
# Tabla de mascotas.
CREATE TABLE pets (id INT AUTO_INCREMENT PRIMARY KEY, owner_id INT, name VARCHAR(100) NOT NULL, species VARCHAR(50), breed VARCHAR(50), age INT, weight DECIMAL(5,2), FOREIGN KEY (owner_id) REFERENCES owners(id));
# Tabla de consultas médicas.
CREATE TABLE consultations (id INT AUTO_INCREMENT PRIMARY KEY, pet_id INT, reason TEXT, diagnosis TEXT, appointment_date DATETIME NOT NULL, FOREIGN KEY (pet_id) REFERENCES pets(id));
# Tabla de roles del sistema.
CREATE TABLE roles (id INT AUTO_INCREMENT PRIMARY KEY, name VARCHAR(50) UNIQUE NOT NULL, permissions TEXT NOT NULL);

# Tabla de bitácora (notas del personal).
CREATE TABLE bitacora (
    id INT AUTO_INCREMENT PRIMARY KEY,
    pet_id INT NOT NULL,
    author VARCHAR(50) NOT NULL,
    note TEXT NOT NULL,
    created_at DATETIME NOT NULL,
    FOREIGN KEY (pet_id) REFERENCES pets(id) ON DELETE CASCADE
);

# Inserta los roles por defecto.
INSERT IGNORE INTO roles (name, permissions) VALUES
('admin', 'all'),
('sistemas', 'all'),
('veterinario', 'ver_pacientes,editar_pacientes'),
('recepcionista', 'ver_pacientes,crear_pacientes');

Paso 2.5: Vincular Maestros
# Obtiene la posición actual del registro binario (Anotar File y Position).
SHOW BINARY LOG STATUS;

# Detiene cualquier replicación previa.
STOP REPLICA;
# Borra cualquier configuración anterior de replicación.
RESET REPLICA ALL;
# Configura db-02 para copiar de db-01 usando la IP, usuario y posición.
CHANGE REPLICATION SOURCE TO SOURCE_HOST='192.168.56.13', SOURCE_USER='replicator', SOURCE_PASSWORD='ReplicaPass123!', SOURCE_LOG_FILE='[File_db01]', SOURCE_LOG_POS=[Pos_db01], GET_SOURCE_PUBLIC_KEY=1;
# Inicia la replicación.
START REPLICA;
# (Hacer lo mismo en db-01 apuntando los datos a la IP de db-02).

3. SERVIDORES DE APLICACIÓN (app-01 y app-02)
═══════════════════════════════════════════════════════════════════════
Objetivo: Correr Flask con Gunicorn como servicio.

Paso 3.1: Instalar dependencias
# Instala Python, pip, herramientas de entorno virtual y Git.
sudo apt install python3-pip python3-venv python3-full git -y

Paso 3.2: Descargar proyecto
# Clona el repositorio de GitHub con el código de la aplicación.
git clone https://github.com/emersonorlando7-cloud/Sistema-Gestion-Veterinaria-VMS.git
# Entra a la carpeta del proyecto.
cd Sistema-Gestion-Veterinaria-VMS
# Crea un entorno virtual aislado para no ensuciar el Python del sistema.
python3 -m venv venv
# Activa el entorno virtual.
source venv/bin/activate
# Instala las librerías necesarias para el proyecto.
pip install -r requirements.txt

Paso 3.3: Crear Servicio Systemd
# Crea el archivo de configuración del servicio.
sudo nano /etc/systemd/system/vetsystem.service

# Contenido del archivo:
[Unit]
Description=Gunicorn instance to serve VetSystem # Descripción del servicio.
After=network.target # Espera a que la red esté lista antes de arrancar.

[Service]
User=servidorjefferson # Usuario del sistema que ejecuta el servicio (cambiar según la VM).
Group=www-data # Grupo del sistema web.
WorkingDirectory=/home/servidorjefferson/Sistema-Gestion-Veterinaria-VMS # Ruta de la carpeta del proyecto.
Environment="PATH=/home/servidorjefferson/Sistema-Gestion-Veterinaria-VMS/venv/bin" # Ruta del entorno virtual.
ExecStart=/home/servidorjefferson/Sistema-Gestion-Veterinaria-VMS/venv/bin/gunicorn --workers 3 --bind 0.0.0.0:5000 app:app # Comando que inicia Gunicorn con 3 workers en el puerto 5000.
Restart=always # Si falla, se reinicia automáticamente.

[Install]
WantedBy=multi-user.target # Se inicia al encender la máquina.

# Recarga los servicios del sistema para que detecte el nuevo archivo.
sudo systemctl daemon-reload
# Inicia el servicio de la aplicación.
sudo systemctl start vetsystem
# Habilita el arranque automático al reiniciar la máquina.
sudo systemctl enable vetsystem

4. BALANCEADOR DE CARGA (lb-01)
═══════════════════════════════════════════════════════════════════════
Objetivo: Distribuir carga web y dar Failover a la BD.

Paso 4.1: Instalar HAProxy
# Instala el balanceador de carga HAProxy.
sudo apt install haproxy -y

Paso 4.2: Configurar
# Abre el archivo de configuración de HAProxy.
sudo nano /etc/haproxy/haproxy.cfg

# Contenido del archivo:
global
    log /dev/log local0 # Guarda logs en el sistema.
    maxconn 4096 # Límite máximo de conexiones simultáneas.
    user haproxy # Usuario con el que corre el servicio.
    group haproxy # Grupo del servicio.
    daemon # Corre en segundo plano como demonio.

defaults
    log global # Usa la configuración global de logs.
    mode http # Modo de tráfico web por defecto.
    option httplog # Formato de logs para HTTP.
    timeout connect 10s # Tiempo máximo para conectar con un servidor.
    timeout client 60s # Tiempo máximo de inactividad del cliente.
    timeout server 60s # Tiempo máximo de inactividad del servidor.

frontend web_frontend
    bind *:80 # Escucha en el puerto 80 (público).
    default_backend web_servers # Envía el tráfico al backend de aplicaciones.

backend web_servers
    balance roundrobin # Alterna las peticiones entre app-01 y app-02.
    cookie SERVERID insert indirect nocache # Mantiene la sesión pegada al servidor que la creó.
    option httpchk GET / # Verifica que la aplicación responda a peticiones HTTP.
    server app-01 192.168.56.11:5000 check cookie s1 # Servidor 1 (le asigna cookie s1).
    server app-02 192.168.56.12:5000 check cookie s2 # Servidor 2 (le asigna cookie s2).

frontend mysql_frontend
    bind *:3306 # Escucha en el puerto de MySQL.
    mode tcp # Modo de tráfico TCP para bases de datos.
    default_backend mysql_servers # Envía el tráfico al backend de bases.

backend mysql_servers
    mode tcp # Tráfico TCP.
    balance first # Usa siempre db-01 como principal.
    option tcp-check # Verifica que el puerto de la base esté abierto.
    timeout server 60s # Tiempo de espera para la base de datos.
    server db-01 192.168.56.13:3306 check # Base principal.
    server db-02 192.168.56.14:3306 check backup # Base de respaldo (solo se usa si db-01 falla).

listen stats
    bind *:8080 # Escucha en el puerto 8080 para el panel web.
    mode http # Tráfico web.
    stats enable # Habilita el panel de estadísticas.
    stats uri /stats # URL para acceder al panel.
    stats auth emerson:@dm1n! # Usuario y contraseña de acceso al panel.

# Valida que el archivo de configuración no tenga errores de sintaxis.
sudo haproxy -c -f /etc/haproxy/haproxy.cfg
# Reinicia HAProxy para aplicar la nueva configuración.
sudo systemctl restart haproxy

5. CONFIGURACIÓN DE FIREWALLS (UFW)
═══════════════════════════════════════════════════════════════════════
Objetivo: Permitir solo el tráfico necesario.

En db-01 y db-02:
# Permite conexiones SSH para administración.
sudo ufw allow 22/tcp
# Permite el acceso a MySQL solo desde la IP del balanceador.
sudo ufw allow from 192.168.56.10 to any port 3306
# Activa el firewall.
sudo ufw enable

En app-01 y app-02:
# Permite conexiones SSH.
sudo ufw allow 22/tcp
# Permite el tráfico web de la aplicación Flask SOLO desde el balanceador.
sudo ufw allow from 192.168.56.10 to any port 5000 proto tcp
# Activa el firewall.
sudo ufw enable

En lb-01:
# Permite conexiones SSH.
sudo ufw allow 22/tcp
# Permite el tráfico web público.
sudo ufw allow 80/tcp
# Permite el tráfico hacia las bases de datos.
sudo ufw allow 3306/tcp
# Permite el acceso al panel de estadísticas.
sudo ufw allow 8080/tcp
# Activa el firewall.
sudo ufw enable

7. SISTEMA DE RESPALDOS AUTOMÁTICOS (RCLONE)
═══════════════════════════════════════════════════════════════════════
Objetivo: Respaldar la base de datos y el código a Google Drive.

Paso 7.1: Instalación y configuración de rclone
# Explicación: Instala rclone en el servidor donde se hará el respaldo (db-01).
sudo apt install rclone -y

# Explicación: Inicia el asistente interactivo para configurar Google Drive.
rclone config

Paso 7.2: Script de respaldo de base de datos (db-01)
# Explicación: Crea el script que hace el dump de MySQL y lo sube a Drive.
sudo nano /usr/local/bin/respaldo_db.sh
# Contenido:
#!/bin/bash
DATE=$(date +%Y-%m-%d)
mysqldump -u root -p'password' vet_clinic_db | gzip > /var/backups/db_${DATE}.sql.gz
/usr/bin/rclone copy /var/backups/ gdrive:VetSystem_Backups/MySQL --include "*.sql.gz"

# Explicación: Da permisos de ejecución.
sudo chmod +x /usr/local/bin/respaldo_db.sh

Paso 7.3: Automatización con Cron
# Explicación: Programa el respaldo automático todos los días a las 2:00 AM.
sudo crontab -e
# Línea a agregar:
0 2 * * * /usr/local/bin/respaldo_db.sh >> /var/log/respaldo_db.log 2>&1

8. SOLUCIÓN DE ERRORES (TROUBLESHOOTING GENERAL)
═══════════════════════════════════════════════════════════════════════
Objetivo: Diagnosticar y resolver los fallos más comunes.

FALLO 1: "502 Bad Gateway" en el navegador al entrar por HAProxy
- CAUSA: HAProxy no puede conectarse a app-01 o app-02. Las apps están caídas.
- SOLUCIÓN: 
  # Explicación: Revisa el estado del servicio en la app afectada.
  sudo systemctl status vetsystem
  # Explicación: Revisa los logs de la app para ver el error exacto.
  sudo journalctl -u vetsystem -n 50 --no-pager

FALLO 2: "OperationalError: Access denied for user 'app_user'"
- CAUSA: Las credenciales en el archivo .env no coinciden con las de MySQL.
- SOLUCIÓN: 
  # Explicación: Verifica la contraseña guardada en el .env.
  cat /ruta/del/proyecto/.env | grep DB_PASSWORD
  # Explicación: Verifica que el usuario exista en MySQL (desde db-01).
  sudo mysql -e "SELECT user, host FROM mysql.user WHERE user='app_user';"

FALLO 3: Error de replicación MySQL (db-02 no sincroniza)
- CAUSA: db-01 se reinició y perdió la posición del log, o hay un conflicto de datos.
- SOLUCIÓN:
  # Explicación: Entra a db-02 y revisa el estado de la réplica.
  sudo mysql
  SHOW REPLICA STATUS\G;
  # Si hay un error (ej. 1062), detén la réplica, salta el error y vuelve a iniciar.
  STOP REPLICA;
  SET GLOBAL sql_slave_skip_counter = 1;
  START REPLICA;

FALLO 4: "No module named 'dotenv'" al arrancar la app
- CAUSA: Las dependencias no se instalaron en el entorno virtual correcto.
- SOLUCIÓN:
  # Explicación: Activa el venv y reinstala las dependencias.
  cd /ruta/del/proyecto
  source venv/bin/activate
  pip install -r requirements.txt
  sudo systemctl restart vetsystem

FALLO 5: No puedo hacer git pull (Error de credenciales)
- CAUSA: GitHub cambió el nombre del repositorio o pide autenticación.
- SOLUCIÓN:
  # Explicación: Actualiza la URL del repositorio remoto.
  git remote set-url origin https://github.com/usuario/NUEVO_NOMBRE_REPO.git
