1. CONFIGURACIÓN DE VIRTUALBOX Y RED (TODOS LOS SERVIDORES)
═══════════════════════════════════════════════════════════════════════
Objetivo: Crear la red privada para que las 5 máquinas se comuniquen.

Paso 1.1: Crear Red Host-Only en VirtualBox
- Ir a Archivo > Herramientas > Administrador de Red.
- Crear red "Solo Anfitrión". IPv4: 192.168.56.1, Máscara: 255.255.255.0, DHCP: Desactivado.

Paso 1.2: Configurar Adaptadores en cada VM
- Adaptador 1: NAT (para internet).
- Adaptador 2: Host-Only (para la red interna del proyecto).

Paso 1.3: Asignar IPs Estáticas (Netplan)
# Explicación: Asigna una dirección IP fija a la tarjeta de red interna para que las máquinas se reconozcan.
# Comandos:
sudo nano /etc/netplan/01-netcfg.yaml # Abre el archivo de configuración de red.

# Contenido del archivo (ejemplo para app-01):
network:
  version: 2 # Versión del formato YAML.
  renderer: networkd # Gestor de red nativo de Ubuntu.
  ethernets:
    enp0s3:
      dhcp4: yes # Interfaz NAT: pide IP automática al router para tener internet.
    enp0s8:
      dhcp4: no # Interfaz Host-Only: IP fija para la red interna.
      addresses:
        - 192.168.56.11/24 # Asigna la IP estática y la máscara de subred.
      nameservers:
        addresses: [8.8.8.8, 1.1.1.1] # Servidores DNS de Google y Cloudflare.

sudo chmod 600 /etc/netplan/01-netcfg.yaml # Permisos de seguridad para que solo root lea el archivo.
sudo netplan apply # Aplica los cambios y activa la nueva IP.

Paso 1.4: Hostnames y /etc/hosts
# Explicación: Asigna un nombre a cada servidor y le dice a las máquinas cómo encontrar a las demás.
# Comandos:
sudo hostnamectl set-hostname app-01 # Cambia el nombre del servidor (ej. app-01, db-01).
sudo nano /etc/hosts # Abre el archivo para mapear las IPs y nombres.

# Contenido del archivo /etc/hosts:
127.0.0.1       localhost
127.0.1.1       app-01 # Nombre local de esta máquina
192.168.56.10   lb-01 # IP del balanceador
192.168.56.11   app-01 # IP de este servidor
192.168.56.12   app-02 # IP del segundo servidor de app
192.168.56.13   db-01 # IP de la base de datos principal
192.168.56.14   db-02 # IP de la base de datos de respaldo

sudo ping db-01 # Comprueba que la red y la resolución de nombres funcionan.

POSIBLES FALLOS Y SOLUCIONES:
- Error "Invalid YAML": Usar solo espacios (no Tab) en el archivo. Alinear los guiones "-" con 2 espacios más que "addresses:".
- El ping no funciona: Revisar que el Adaptador 2 esté conectado y que los archivos /etc/hosts estén idénticos en todas las máquinas.

2. SERVIDORES DE BASE DE DATOS (db-01 y db-02)
═══════════════════════════════════════════════════════════════════════
Objetivo: Configurar la replicación y las tablas para citas y roles.

Paso 2.1: Instalación
# Explicación: Actualiza el sistema e instala el servidor de base de datos MySQL.
sudo apt update # Actualiza la lista de paquetes disponibles.
sudo apt install mysql-server -y # Instala MySQL sin pedir confirmación.

Paso 2.2: Configuración de mysqld.cnf
# Explicación: Configura MySQL para aceptar conexiones externas y preparar la replicación.
sudo nano /etc/mysql/mysql.conf.d/mysqld.cnf # Abre el archivo de configuración.

# Agrega debajo de [mysqld]:
[mysqld]
server-id = 1 # Identificador único del servidor. En db-01 es 1, en db-02 es 2.
bind-address = 0.0.0.0 # Permite que MySQL acepte conexiones desde cualquier IP (necesario para HAProxy).
max_connect_errors = 100000 # Aumenta el límite de errores de red para evitar bloqueos.

sudo systemctl restart mysql # Reinicia el servicio para aplicar los cambios.

Paso 2.3: Creación de Usuarios
# Explicación: Crea los usuarios necesarios para la replicación y para que la app se conecte.
sudo mysql # Entra a la consola de MySQL como administrador.

# Usuario para la replicación:
CREATE USER 'replicator'@'%' IDENTIFIED WITH caching_sha2_password BY 'ReplicaPass123!'; # Crea usuario replicador.
GRANT REPLICATION SLAVE ON *.* TO 'replicator'@'%'; # Le da permiso para copiar datos.

# Usuario para la aplicación:
CREATE USER 'app_user'@'%' IDENTIFIED WITH caching_sha2_password BY 'AppPass123!'; # Crea usuario de la app.
CREATE USER 'app_user'@'192.168.56.10' IDENTIFIED WITH caching_sha2_password BY 'AppPass123!'; # Permite que HAProxy se conecte.
GRANT ALL PRIVILEGES ON vet_clinic_db.* TO 'app_user'@'%'; # Da permisos totales en la base.
GRANT ALL PRIVILEGES ON vet_clinic_db.* TO 'app_user'@'192.168.56.10'; # Permisos específicos para HAProxy.
FLUSH PRIVILEGES; # Recarga los permisos.
EXIT; # Sale de MySQL.

Paso 2.4: Creación de Base de Datos y Tablas (Solo en db-01)
# Explicación: Crea la base de datos y las tablas donde se guardará la información.
CREATE DATABASE vet_clinic_db; # Crea la base de datos.
USE vet_clinic_db; # Selecciona la base de datos.

# Tablas originales:
CREATE TABLE users (id INT AUTO_INCREMENT PRIMARY KEY, username VARCHAR(50) UNIQUE NOT NULL, password_hash VARCHAR(255) NOT NULL, role VARCHAR(50) NOT NULL); # Tabla de usuarios.
CREATE TABLE owners (id INT AUTO_INCREMENT PRIMARY KEY, name VARCHAR(100) NOT NULL, phone VARCHAR(20), email VARCHAR(100), address VARCHAR(255)); # Tabla de dueños.
CREATE TABLE pets (id INT AUTO_INCREMENT PRIMARY KEY, owner_id INT, name VARCHAR(100) NOT NULL, species VARCHAR(50), breed VARCHAR(50), age INT, weight DECIMAL(5,2), FOREIGN KEY (owner_id) REFERENCES owners(id)); # Tabla de mascotas.

# Tabla de consultas con fecha y hora de la cita.
CREATE TABLE consultations (
    id INT AUTO_INCREMENT PRIMARY KEY,
    pet_id INT,
    reason TEXT,
    diagnosis TEXT,
    appointment_date DATETIME NOT NULL, # Almacena la fecha y hora exacta de la cita.
    FOREIGN KEY (pet_id) REFERENCES pets(id)
);

# Tabla de roles para permisos dinámicos.
CREATE TABLE roles (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) UNIQUE NOT NULL, # Nombre del rol (ej. secretaria).
    permissions TEXT NOT NULL # Guarda los permisos separados por coma.
);

# Inserta los roles base del sistema.
INSERT IGNORE INTO roles (name, permissions) VALUES 
('admin', 'all'),
('sistemas', 'all'),
('veterinario', 'ver_pacientes,editar_pacientes'),
('recepcionista', 'ver_pacientes,crear_pacientes');

Paso 2.5: Vincular Maestros
# Explicación: Conecta ambos servidores para que se copien los datos mutuamente.
# (En db-01): 
SHOW BINARY LOG STATUS; # Obtiene la posición actual del registro (Anotar File y Position).

# (En db-02):
STOP REPLICA; # Detiene cualquier replicación previa.
RESET REPLICA ALL; # Borra la configuración anterior.
CHANGE REPLICATION SOURCE TO SOURCE_HOST='192.168.56.13', SOURCE_USER='replicator', SOURCE_PASSWORD='ReplicaPass123!', SOURCE_LOG_FILE='[File_db01]', SOURCE_LOG_POS=[Pos_db01], GET_SOURCE_PUBLIC_KEY=1; # Configura db-02 para copiar de db-01.
START REPLICA; # Inicia la replicación.
# (Hacer lo mismo en db-01 apuntando los datos a la IP de db-02).

POSIBLES FALLOS Y SOLUCIONES:
- "Unknown variable 'log_bin'": MySQL 8.4 eliminó esta variable. Borrarla.
- "Plugin 'mysql_native_password' is not loaded": Usar caching_sha2_password por defecto.
- "Access denied for user 'app_user'@'lb-01'": Crear el usuario para la IP 192.168.56.10.
- Error 2013 (Lost connection): Tener timeouts altos en HAProxy y la lógica de reintento en Python.

3. SERVIDORES DE APLICACIÓN (app-01 y app-02)
═══════════════════════════════════════════════════════════════════════
Objetivo: Correr Flask con Gunicorn como servicio.

Paso 3.1: Instalar dependencias
sudo apt install python3-pip python3-venv python3.14-venv git -y # Instala Python, pip, entorno virtual y Git.

Paso 3.2: Descargar proyecto
# Explicación: Descarga el código fuente de la aplicación desde GitHub.
git clone https://github.com/emersonorlando7-cloud/VetSystem_APP.git # Descarga el repositorio.
cd VetSystem_APP # Entra a la carpeta del proyecto.
python3 -m venv venv # Crea un entorno virtual aislado.
source venv/bin/activate # Activa el entorno virtual.
pip install flask flask-sqlalchemy pymysql gunicorn # Instala las librerías necesarias.

Paso 3.3: Crear Servicio Systemd
# Explicación: Convierte la aplicación en un servicio de Linux para que arranque automáticamente.
sudo nano /etc/systemd/system/vetsystem.service # Crea el archivo de configuración.

# Contenido del archivo:
[Unit]
Description=Gunicorn instance to serve VetSystem # Descripción del servicio.
After=network.target # Espera a que la red esté lista antes de arrancar.

[Service]
User=servidorjefferson # Cambiar por el usuario real (servidorangel en app-02).
Group=www-data # Grupo del sistema web.
WorkingDirectory=/home/servidorjefferson/VetSystem_APP # Ruta de la carpeta del proyecto.
Environment="PATH=/home/servidorjefferson/VetSystem_APP/venv/bin" # Ruta del entorno virtual.
ExecStart=/home/servidorjefferson/VetSystem_APP/venv/bin/gunicorn --workers 3 --bind 0.0.0.0:5000 app:app # Comando que inicia Flask.
Restart=always # Si falla, se reinicia automáticamente.

[Install]
WantedBy=multi-user.target # Se inicia al encender la máquina.

sudo systemctl daemon-reload # Recarga los servicios del sistema.
sudo systemctl start vetsystem # Inicia la aplicación.
sudo systemctl enable vetsystem # Habilita el arranque automático.

POSIBLES FALLOS Y SOLUCIONES:
- "TemplateNotFound": Faltan archivos HTML. Revisar la carpeta 'templates'.
- Error 500 al editar: Ocurre al dejar campos numéricos vacíos. Solución: Usar int(age) if age else None.
- Error 1451 al eliminar: Ocurre por llaves foráneas. Solución: Borrar consultas antes de mascota y usar flush().
- Página en blanco o 503: Revisar con sudo systemctl status vetsystem y reiniciar.

4. BALANCEADOR DE CARGA (lb-01)
═══════════════════════════════════════════════════════════════════════
Objetivo: Distribuir carga web y dar Failover a la BD.

Paso 4.1: Instalar HAProxy
sudo apt install haproxy -y # Instala HAProxy.

Paso 4.2: Configurar
# Explicación: Configura HAProxy para repartir tráfico web y conmutar la base de datos.
sudo nano /etc/haproxy/haproxy.cfg # Abre el archivo de configuración.

# Contenido del archivo:
global
    log /dev/log local0 # Guarda logs en el sistema.
    maxconn 4096 # Límite máximo de conexiones simultáneas.
    user haproxy # Usuario con el que corre el servicio.
    group haproxy # Grupo del servicio.
    daemon # Corre en segundo plano.

defaults
    log global # Usa la configuración global de logs.
    mode http # Modo de tráfico web por defecto.
    option httplog # Formato de logs para HTTP.
    timeout connect 10s # Tiempo máximo para conectar con un servidor.
    timeout client 60s # Tiempo máximo de inactividad del cliente.
    timeout server 60s # Tiempo máximo de inactividad del servidor.

frontend web_frontend
    bind *:80 # Escucha en el puerto 80 (público).
    default_backend web_servers # Envía el tráfico al backend de aplicaciones.

backend web_servers
    balance roundrobin # Alterna las peticiones entre app-01 y app-02.
    option httpchk GET / # Verifica que la app responda (HTTP 200).
    server app-01 192.168.56.11:5000 check # Servidor 1 (verifica estado).
    server app-02 192.168.56.12:5000 check # Servidor 2 (verifica estado).

frontend mysql_frontend
    bind *:3306 # Escucha en el puerto de MySQL.
    mode tcp # Modo de tráfico TCP (para bases de datos).
    default_backend mysql_servers # Envía el tráfico al backend de bases.

backend mysql_servers
    mode tcp # Tráfico TCP.
    balance first # Usa siempre db-01. Si falla, usa db-02.
    option tcp-check # Verifica que el puerto esté abierto.
    timeout server 60s # Tiempo de espera para la base de datos.
    server db-01 192.168.56.13:3306 check # Base principal.
    server db-02 192.168.56.14:3306 check backup # Base de respaldo.

listen stats
    bind *:8080 # Escucha en el puerto 8080 para las estadísticas.
    mode http # Tráfico web.
    stats enable # Habilita el panel de estadísticas.
    stats uri /stats # URL para acceder (/stats).
    stats auth emerson:@dm1n! # Usuario y contraseña de acceso.

sudo haproxy -c -f /etc/haproxy/haproxy.cfg # Valida que el archivo no tenga errores.
sudo systemctl restart haproxy # Reinicia HAProxy para aplicar los cambios.

POSIBLES FALLOS Y SOLUCIONES:
- "unknown keyword 'balace'": Error de tipeo. Corregir a 'balance'.
- "stats parameter 'anable'": Error de tipeo. Corregir a 'enable'.
- "backend 'mysql_servers' has the same name": Se duplicó el bloque. Borrar el duplicado.
- Las apps o bases en rojo: Revisar que los servicios estén corriendo y los firewalls permitan el tráfico.

5. CONFIGURACIÓN DE FIREWALLS (UFW)
═══════════════════════════════════════════════════════════════════════
Objetivo: Permitir solo el tráfico necesario.

En db-01 y db-02:
sudo ufw allow 22/tcp # Permite conexiones SSH.
sudo ufw allow from 192.168.56.10 to any port 3306 # Permite solo a HAProxy acceder a MySQL.
sudo ufw enable # Activa el firewall.

En app-01 y app-02:
sudo ufw allow 22/tcp # Permite conexiones SSH.
sudo ufw allow 5000/tcp # Permite el tráfico de la aplicación Flask.
sudo ufw enable # Activa el firewall.

En lb-01:
sudo ufw allow 22/tcp # Permite conexiones SSH.
sudo ufw allow 80/tcp # Permite el tráfico web público.
sudo ufw allow 3306/tcp # Permite el tráfico hacia las bases de datos.
sudo ufw allow 8080/tcp # Permite el acceso al panel de estadísticas.
sudo ufw enable # Activa el firewall.

6. EXPOSICIÓN A INTERNET (NGROK)
═══════════════════════════════════════════════════════════════════════
Objetivo: Dar un enlace público a lb-01 sin abrir puertos en el router.

Instalación en lb-01:
wget https://bin.equinox.io/c/bNyj1mQVY4c/ngrok-v3-stable-linux-amd64.tgz # Descarga Ngrok.
tar -xvzf ngrok-v3-stable-linux-amd64.tgz # Descomprime el archivo.
sudo mv ngrok /usr/local/bin/ # Mueve el ejecutable a una carpeta del sistema.

Autenticación:
ngrok config add-authtoken TU_TOKEN_AQUI # Guarda tu token de autenticación.

Servicio permanente:
sudo nano /etc/systemd/system/ngrok.service # Crea el archivo de servicio.

# Contenido del archivo:
[Unit]
Description=Ngrok Tunnel for VetSystem # Descripción.
After=network.target # Espera a la red.

[Service]
User=servidoremerson # Usuario de lb-01.
ExecStart=/usr/local/bin/ngrok http 80 --url=https://tu-dominio.ngrok-free.dev # Comando que abre el túnel al puerto 80 con dominio fijo.
Restart=always # Si se cae, se reinicia.
RestartSec=10 # Espera 10s antes de reiniciar.

[Install]
WantedBy=multi-user.target # Arranca con el sistema.

sudo systemctl daemon-reload # Recarga el sistema.
sudo systemctl enable ngrok # Habilita el arranque automático.
sudo systemctl start ngrok # Inicia el túnel.

7. SOLUCIÓN DE ERRORES (TROUBLESHOOTING GENERAL)
═══════════════════════════════════════════════════════════════════════
A. "504 Gateway Timeout" o página no carga:
   - Causa: HAProxy no puede conectar con las apps.
   - Solución: Verificar que vetsystem.service esté activo en app-01 y app-02.

B. Error 500 en Flask (Pantalla blanca):
   - Causa: Error interno en el código (ej. campos vacíos).
   - Solución: Agregar try...except en app.py. Revisar journalctl -u vetsystem -n 50.

C. Base de datos bloqueada por errores:
   - Causa: MySQL bloquea IPs por múltiples intentos fallidos.
   - Solución: En MySQL, ejecutar TRUNCATE TABLE performance_schema.host_cache; y reiniciar HAProxy.

D. La página dice "Lost connection to MySQL" (2013):
   - Causa: Se apagó una base abruptamente y la conexión en memoria murió.
   - Solución: La app tiene bucle de reintento (time.sleep(1)) y PRE_PING.

E. Al editar campos se genera error 500:
   - Causa: Dejar vacíos los campos de Edad o Peso (columnas numéricas).
   - Solución: Convertir a None si están vacíos: pet.age = int(age) if age else None.

F. No se puede eliminar un paciente (Error 1451):
   - Causa: El paciente tiene consultas médicas asociadas (llave foránea).
   - Solución: Borrar las consultas primero y usar db.session.flush().

G. No aparece el aviso cuando un usuario sin permisos entra a una sección:
   - Causa: Antes se usaba flash() y redirect(), lo que hacía que la página cambiara y el mensaje apareciera después.
   - Solución: Se modificó el decorador @permission_required en app.py para que devuelva un script de JavaScript que lanza una alerta inmediata (alert()) y devuelve al usuario a la página anterior (history.back()).
